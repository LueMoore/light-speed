# 光速渲染实验

把光速调到 **1 m/s**，看看世界会变成什么样。

一个单文件 WebGL 演示（`light-speed.html`），实时渲染"有限光速"下的视觉畸变。不需要构建、不需要依赖。

👉 **[点击这里体验在线演示](https://luemoore.github.io/light-speed/)**

---

## 它演示什么

日常世界里光速太快，我们看到的一切几乎都是"此刻"。把光速降到 1 m/s 后，**5 米外的物体，你看到的是它 5 秒前的位置**。

场景里有 6 个球绕你公转。当光速足够慢，你会看到：

- **位置错位**：球出现在它早已离开的地方
- **形状扭曲**：球面各点到你的距离不同，到达时间也不同，球被剪切拉伸
- **方向反转**：球远离你时光追得吃力，靠近时轻松，视觉运动方向可能与真实相反
- **物体消失**：球速超过光速时，光根本追不上它

## 核心原理

渲染器做的不是后期特效，是**时空光线追踪**（retarded time）。

每条像素射线当作一束真实的光，沿直线以 `c` 前进。射线参数 `s` 直接对应光的传播时间：

```
tau = t0 - s / c
```

球体的位置必须用 `ballPos(tau)` 求，也就是**光离开它的那一刻**它在哪，而不是它现在在哪。光照同理：从交点回溯光源时，要迭代求解"这束光是什么时候离开光源的"，所以连阴影都是错位的。

地面是静止的，作为参照物。

## 面板参数

**光速**：0.5 – 400 m/s。拖到 1 附近效果最强烈。

**物体运动速度**：0.05× – 3.0×，改变球体角速度。这个值和光速的**比值**决定了错位程度——球速越接近光速，画面撕得越开。

**虚影**：调好光速后按 `G`，会留下一个该光速下的位置标记。叠加多个就能看出"光速变化时球会滑到哪里"。虚影是玻璃球轮廓，不遮挡实心球。

**延迟着色**：把画面按"这束光走了多久"上色，蓝→青→绿→黄→红对应 0→26 秒。

**小地图**：实心点是球的真实位置，空心圈是你此刻看到的位置，连线是那束光走过的路。扇形是当前视野范围。

## 实现要点

- **WebGL 1.0 / GLSL ES 1.0**，单文件，零外部依赖
- 球体求交用 sphere tracing，命中后用解析二次方程精修一次（球在动，SDF 的 Lipschitz 常数约 `1 + v/c`，固定步长在高速时会穿透）
- 虚影是固定时刻的快照，位置已知，直接用解析求交，成本极低
- 分辨率自适应：按平均帧时间在 0.42–1.0 之间动态调整渲染缩放
- 小地图可视半径随相机远离自动放大，避免球跑出画面

## 运行

```
直接用浏览器打开 light-speed.html
```

第一人称需要指针锁定。在 iframe 里预览时通常会被拒（缺少 `allow="pointer-lock"`），此时会自动降级为拖动环视。想要完整体验，用浏览器直接打开文件即可。

## 一点说明

这个演示**不考虑相对论**。也就是说：

- 没有长度收缩、没有时间膨胀
- 没有光速不变原理（相对运动时 `c` 不随之改变）
- 没有多普勒效应、没有 Terrell 旋转

`c` 只是被单独调慢的一个"信号传播速度"，其他物理量一概不动。这是一个思想实验，不是预言。

顺带一提，如果光速真的变成 1 m/s，原子核与电子之间的电磁力也以这个速度传播，物质会当场散架——**根本不会有"看"这回事**。

## ⚠️ 性能与注意事项

- **极度吃显卡**：因为每一帧都在做海量的光线步进循环，建议使用**电脑端**独立显卡或性能较好的核显打开。
- **手机端警告**：如果在手机浏览器打开，可能会严重掉帧甚至导致设备发热。
- 如果画面卡顿，可以尝试缩小浏览器窗口，或在代码中降低 Raymarching 的步进次数。
